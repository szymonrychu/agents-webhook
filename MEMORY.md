# agents-webhook memory

Lessons that outlive a session. Newest first.

- 2026-11-01 (webhook-ingress-auth): every endpoint has an `auth_mode` (`basic`, `header`, `bearer`, `hmac`). Why: GitLab sends `X-Gitlab-Token` (and GitHub/Grafana sign with HMAC), so the basic-only ingest answered 401 on the correct URL; the earlier 503s were a wrong URL. Decisions: (1) non-basic secrets are server-generated only and stored AES-256-GCM encrypted in `secret_ct` (nonce || ciphertext || tag) with the endpoint id as AAD (`secrets_box.py`, key from `WEBHOOK_ENDPOINT_KEY_FILE`, a Secret mounted on ingest and api, never the worker); `secret_kid` is a key fingerprint for a later re-encrypt (rotation tooling not built; losing the key means rotating every secret). The id is reserved with `nextval` so the row and its ciphertext are one INSERT. (2) Existing basic rows migrate in place (0006), scrypt hash untouched; a CHECK ties the columns to the mode and `username`/`password_hash` became nullable. (3) Verification is `ingest/auth.py`, one verifier per mode, compares on SHA-256 digests via `hmac.compare_digest`; every failed path, including an unknown suffix, ends in exactly one scrypt (basic does it naturally, the others run `DUMMY_HASH`), so the identical 401 body and the timing do not say which check failed; `WWW-Authenticate: Basic` is sent for every 401. (4) hmac signs the raw body bytes as received, so ingest reads the body (capped) before auth for hmac endpoints only, after the limiter; a body over the cap cannot be verified and is the same 401 rather than a 413, so a probe cannot learn a suffix exists. With `hmac_timestamp_header` (Grafana) the signed message is `<ts>:<body>` and the timestamp must be within `WEBHOOK_HMAC_REPLAY_SECONDS`. (5) PATCH changes every field except the secret; an `auth_mode` change starts the new mode's fields from the body alone and issues a new secret, shown once; clone copies config but never hash, ciphertext or username. Not done: GitLab signing token (`webhook-signature`, wire format not verified), key rotation tooling.

- 2026-10-31 (superleader-crud WH1): `api` can serve a second, token-gated listener (`WEBHOOK_ADMIN_TOKENS_FILE`, `WEBHOOK_ADMIN_PORT`, agents-common v0.6.0 `ServiceTokenGate`) mounting the same router as the UI app, so the orchestrator relay can CRUD webhooks without SSO. It has no source allowlist (the token is the gate) and returns passwords on create and rotate like the UI port; the orchestrator strips them (D9). Off unless a tokens file is set; names mirror agents-schedule's `SCHED_ADMIN_*`. Why: the superleader agent needs CRUD without a human session.

- 2026-10-31 (agents-ui-improvements B1): the template sandbox (bounded env, child process, time and memory caps, `from_json`) lives in `agents_common.templating` (v0.5.0); `prompt.py` keeps only the event block and the context builder, and `prompt.TemplateError` is common's. Why: one sandbox for webhook, schedule, matrix and orchestrator, fixed once. `validate_template` still raises `ValueError` for the routes.
- 2026-10-28 (semver-image-tags-at-the-end D1-D9): every green main build ends with `release` (needs every other job, `contents: write`, concurrency group `release`, full history and tags). Why: Harbor retention pruned the deployed sha7 tags within hours (incident 2026-10-28, `838ba1f` among them); semver tags survive it. `scripts/next_version.py` and `tests/test_next_version.py` are byte-identical copies of agents-orchestrator's: never edit them here, change them there and copy. Rules: `!` or a BREAKING CHANGE footer is major (also on 0.x), `feat` minor, else patch, over every commit since the highest reachable `vX.Y.Z` (not first-parent); first release exactly 0.1.0 with no history scan (a full scan would start at 1.0.0: history holds `feat!` commits); nothing printed when HEAD is already contained in a release tag, because concurrency serializes release jobs but not their order. Retag with `regctl image copy` (manifest only) first, lightweight git tag (checkout token, never `secrets.GITHUB_TOKEN`) last, so a failed run leaves no tag and a re-run repeats the idempotent copies. Retired: the `push: tags: [v*]` trigger, `chart-publish-tag` and chart-version.sh's tag mode; the release job owns `v*` tags, a GITHUB_TOKEN tag push starts no workflow, and the tag job's Chart.yaml equality check would have refused every release. Main `chart-publish` stays.
- 2026-10-25: the orchestrator's unit is a session and the project is agents-orchestrator (design D1, D2). Run columns are `session_id`/`session_slug` (migration 0005 renames them in place, rows kept), the worker runs on agents-common v0.3.0 sessions, and no alias keeps the old names. `tests/test_nomenclature.py` guards every tracked file except dated history and the applied migrations 0001 and 0005. Why: one vocabulary across services, and no backward compatibility.
- 2026-10-25: events about the same item are deduplicated per endpoint by `dedup_key` (repo, kind, number; Grafana: alert group digest). A queued `new` row is replaced by the newest delivery (latest wins) and the older delivery is recorded `ignored/duplicate`; the same delivery id again is `duplicate` too (D5). Why: bursts of edits should start one run with the latest data.
- 2026-10-25: agent reuse is opt-in per preset (`reuse_running_agent`, D16). A queued event of an item with an earlier run is posted as an update to that run's running cluster, bypassing the caps; a gone or refusing cluster falls back once to a new cluster, recorded as `reuse_fallback`. Why: reuse changes what an agent sees, so the operator chooses it per preset; default off keeps one cluster per event.
- 2026-10-25: limits are settings with defaults 3 in progress overall, 1 per endpoint, queue cap 500, body cap 5 MiB (D6), set from chart `limits.*`. Over-cap bodies get 413 after authentication; a full queue records `ignored/queue_full` rather than refusing the sender.
- 2026-10-25: ingest and api are separate Deployments of one image (D2). Why: ingest is public without SSO and must hold no orchestrator token and expose no management routes; api is behind SSO. The worker is a singleton by advisory lock.
- 2026-10-25: per-webhook endpoints (`/webhook/<suffix>`, one type, one preset, basic auth) replace per-source secrets and mappings (D3, D7). Why: GitHub, GitLab and Grafana all can send basic auth in the URL or contact point, and one endpoint per use case needs no mapping layer. Passwords are scrypt-hashed and shown once; unknown suffix and wrong credentials answer identically.
- 2026-10-25: dispatch is idempotent through a marker in the posted prompt (D8): a crash between create-cluster and post resumes without a second cluster or a second prompt (`runs.dispatch`, `runs.deliver` adopt before posting).
- 2026-10-25: `WEBHOOK_EVENTS_RETENTION_DAYS` is declared in settings but nothing prunes events yet.
- 2026-10-25: per-endpoint filters (allow and deny rules, `equals` or RE2 `regex`; a filtered delivery is stored `ignored` with `filter_denied`/`filter_not_allowed`) replace `WEBHOOK_ALLOWED_AUTHORS` and its reason `author_not_allowed`, removed with no alias (gate Q1); an author allowlist is an endpoint `allow` rule on `author`. `WEBHOOK_BOT_LOGINS` stays global as the self-loop guard (`self_event`). Why: one way to allowlist authors, scoped per endpoint, and no backward compatibility; `extra="ignore"` makes a leftover env var inert.
